# PhotoFrame

Слайд-шоу для цифровой фоторамки на Android 8.1 (Frameo): снимки из публично
расшаренного альбома Google Photos, с сервера Immich и из папок на устройстве, плюс
часы, дата, датчики Home Assistant и живой поток камеры.

.NET 10 MAUI, только Android: `net10.0-android`, minSdk 27, ABI `armeabi-v7a`.

## Источники снимков

Источники включаются в настройках прямо на рамке и объединяются в одно слайд-шоу;
включить можно несколько сразу.

- **Общий альбом Google Photos.** Рамка забирает страницу расшаренного альбома, достаёт
  из неё прямые ссылки на снимки и скачивает их под своё разрешение. Авторизация не нужна.
- **Immich.** Свой сервер: список объектов приходит JSON-ом, ключ передаётся заголовком
  `x-api-key`. Показывать можно всю библиотеку или выбранные альбомы — список альбомов
  запрашивается кнопкой в настройках.

  Отмеченные альбомы запрашиваются по одному и склеиваются на рамке с отсевом повторов:
  сервер понимает список как «снимок сразу во всех этих альбомах», а нужно «в любом из них».
  Содержимое альбома берётся постраничным поиском с фильтром `albumIds`.

  Качается `preview` — JPEG около 1440 пикселей по длинной стороне; для экрана 1280x800
  этого достаточно. Съёмочные данные запрашиваются флагом `withExif`. Клип берётся
  с `/video/playback`, то есть перекодированным в H.264.

  Рядом с кэшем лежит `immich.index` — таблица с табуляцией: имя файла в кэше,
  идентификатор объекта, вид, длительность, дата съёмки, камера, альбом и исходное имя.
  Кадр подписывается альбомом.
- **Папки на устройстве.** Одна или несколько папок, при желании с вложенными. Папки
  выбираются встроенным обзором памяти: под каждой видно, сколько в ней изображений и
  сколько во вложенных. Файлы не копируются — рамка показывает их на месте.
  При обходе пропускаются каталоги `cache`, `*thumbnail*`, `Trash` и скрытые.

Источники независимы: если Wi-Fi недоступен, а папки на месте, слайд-шоу продолжает
работать по локальным снимкам и лишь сообщает, что альбом не прочитан.

Результат проверки, ход загрузки и ошибки показываются всплывающим сообщением внизу
экрана; оно гаснет через пять секунд. Ночью сообщения не показываются.

## Как показывается кадр

Слайд-шоу устроено в два слоя: новый снимок проявляется поверх прежнего, поэтому между
кадрами нет чёрного экрана. Кадр читается в фоне и отдаётся платформенному `ImageView`
уже готовым.

Читает снимок свой декодер и сразу уменьшает его под экран: `BitmapFactory` с `inSampleSize`
не даёт полноразмерному кадру появиться в памяти. Поворот из EXIF применяется вручную.

## Живой поток камеры

Камеру можно смотреть прямо на рамке — кнопка 📷 в панели управления. Источника два.

**Home Assistant.** Рамка забирает у него список камер (`camera.*`) и показывает выбранную;
переключение — кнопкой «След. камера». Чем играть поток, решает сама Home Assistant: либо
HLS-плейлист (`camera/stream`), который играет ExoPlayer, либо MJPEG одним долгим соединением
(`camera_proxy_stream`). Атрибут `frontend_stream_type` заполнен не у всех камер, поэтому рамка
на него не полагается, а пробует по очереди. Поток не открылся или оборвался — рамка
перезапускает его (до трёх попыток с короткой паузой) и на время переподключения показывает
свежий снимок. Если живого потока нет вовсе, остаются снимки по таймеру.

**IP-камера напрямую (RTSP).** Второй способ — играть поток самому, минуя перекодировку Home
Assistant. Адрес вида `rtsp://user:пароль@192.168.1.50:554/stream1`; в списке такой источник
идёт первым и Home Assistant не требует. Если камера отключилась, рамка продолжает пробовать
её RTSP по кругу.

Адрес и название прямой камеры можно положить файлами в память рамки (копируются по USB):
`PhotoFrame/camera_rtsp.txt` и `PhotoFrame/camera_rtsp_name.txt`. Так же кладутся токен Home
Assistant (`homeassistant.key`) и ключ Immich (`immich.key`, принимается и `immich_key.txt`).

**Ограничения.** Рамка играет то, что умеет её декодер: H.264 и HEVC, оба аппаратно, до
1920x1088. Камера должна быть доступна рамке по сети напрямую, а учётные данные в адресе — те,
что камера принимает для потока (у Dahua, например, это digest-авторизация).

## Часы, дата и подписи

Поверх снимка показываются часы и дата; текст обведён контуром, чтобы читаться на любом
фоне. Угол выбирается по самому снимку: для каждого из четырёх углов считается дисперсия
яркости и доля пикселей телесного оттенка, чтобы не накрывать цифрами лица. Разбор идёт
по уменьшенной копии кадра в фоновом потоке; если он не удался, часы переезжают в следующий
угол по кругу.

Под датой выводятся показания выбранных датчиков Home Assistant; они обновляются вместе
со сменой минуты. Количество датчиков не ограничено, строка переносится по словам, а от пяти
выбранных значения читаются одним запросом `/api/states`. Значки идут по три в строке;
порядок задаётся стрелками на экране выбора датчиков.

В левом нижнем углу — чем и когда снят кадр (камера и дата съёмки из EXIF, для видео — дата
из контейнера). Этот угол закреплён и не переезжает вместе с часами; строка появляется только
когда данные есть.

## Ночной режим

Ночью (по умолчанию 22:00–07:00) слайд-шоу заменяется часами на весь экран. У них шахматная
маска: горит только каждый второй пиксель, и на каждом обновлении времени маска инвертируется —
это вдвое снижает яркость и не даёт статичной картинке выгорать. Двоеточие гаснет раз в секунду:
кадр минуты рисуется дважды, с двоеточием и без, а мигание лишь подменяет готовую картинку.

Показания датчиков рисуются в самом кадре часов, под датой, — так они получают и цвет часов,
и шахматную маску. Кадр часов рисуется в один из двух заранее заведённых буферов;
bitmap'ы освобождаются через `Recycle`.

Вместе с этим приглушается подсветка: у рамки она управляемая (`/sys/class/backlight`,
256 шагов), и яркость задаётся окну, а не системе. Насыщенность самих цифр — отдельная
настройка: подсветка упирается в предел устройства, и дальше гасить можно только краской.

## Видео и живые фото

Из локальных папок показываются не только снимки, но и видео
(`.mp4`, `.m4v`, `.3gp`, `.webm`, `.mkv`). Видео начинается само, как только слайд-шоу до него
дошло, и по окончании рамка переходит к следующему кадру. Пока видео играет или стоит на паузе,
кадры не сменяются; при включённом повторе видео идёт по кругу. Звук по умолчанию выключен.

Пока проигрыватель готовится, виден кадр-заставка из самого файла. Под кнопкой воспроизведения —
полоса позиции с текущим временем и длительностью; позиция опрашивается раз в полсекунды.

Проигрыватель — обёртка над ExoPlayer (Media3): он идёт к декодерам через MediaCodec
и сам выбирает дорожку. Клипы из альбома и Immich забираются тогда, когда слайд дошёл
до экрана; пока идёт загрузка, на экране заставка и полоса прогресса, а скачанный клип
остаётся в `PhotoFrame/Cache` и на следующем круге играет сразу.

VP9 рамка не воспроизводит: единственный декодер на него программный и ограничен 720x480.
Отказ запоминается — файл удаляется, кадр остаётся снимком.

Видео из общего альбома Google Photos не воспроизводятся: страница альбома отдаёт для них
только кадр-заставку, а не ссылку на поток.

«Живые фото» — снимки с приложенными секундами движения — по умолчанию остаются снимками.
Включённые, они проигрываются один раз в начале слайда и дальше остаются обычным кадром.

После включения рамки показ продолжается с того кадра, на котором остановился, и в том же
порядке: порядок лежит в файле, последний кадр — в настройках. Сохранённый порядок принимается,
только если набор кадров совпал целиком. Переключатель случайного порядка пересобирает очередь
сразу.

## Настройки на устройстве

и переживает обновление приложения.

Разделы свёрнуты и раскрываются нажатием на заголовок: настроек столько, что список
перестал помещаться на экран. Разделы сгруппированы по тому, чем управляют, и под каждым
заголовком подписано, что внутри: яркость и размер кадра — в «Экране», камеры — в
«Камерах», подключение Home Assistant — в его собственном разделе.

## Корзина

🗑 не удаляет файл, а переносит его в `PhotoFrame/Trash` в общей памяти устройства, спросив
подтверждение. Папку видно с компьютера по USB, и удаление приложения снимки из неё не уносит.

Кадры из общего альбома складываются в подкаталог `Trash/Google Photos`, а их имена
запоминаются и отбрасываются при разборе альбома — иначе следующая синхронизация скачала бы
снимок заново. В счётчик «из N в альбоме» они тоже не попадают.

Кадр Immich уходит в корзину **самого сервера** (`DELETE /api/assets`, `force=false`),
а с рамки просто удаляется вместе со своим клипом; восстановленный на сервере объект
возвращается на рамку при очередной синхронизации. Если сервер удалить отказался (ключ
без права на удаление), кадр вносится в список убранных.

В разделе «О программе» видно, сколько файлов лежит в корзине и сколько они занимают,
и есть кнопка очистки с подтверждением. Обход папок не заходит в каталоги с именем `Trash`.

После переноса вызывается `MediaScannerConnection.ScanFile` сразу для двух путей — нового
и исчезнувшего: MTP отдаёт компьютеру индекс MediaStore, а не файловую систему, и без этого
по USB файл не виден, а галереи показывают снимок, которого уже нет. Переиндексировать корзину
вручную нужно именно по файлам: `am broadcast` для каталога заводит запись с `format=12288`
вместо `12289`, и по USB такая папка не открывается.

```bash
adb shell 'find /storage/emulated/0/PhotoFrame/Trash -type f | while IFS= read -r f; do am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d "file://$(echo "$f" | sed "s/ /%20/g")" >/dev/null; done'
```

## Сведения о файле

Кнопка ℹ показывает всё, что известно о текущем кадре: имя, папку, размер, дату изменения;
для снимков — разрешение и EXIF (когда снято, камера, выдержка, диафрагма, ISO, фокусное
расстояние, вспышка, координаты), для видео — длительность, разрешение, битрейт, поворот,
наличие звука. Пустые поля не показываются.

Ручное переключение кадра перезапускает таймер показа. Кнопка «назад» на экране слайд-шоу
заблокирована: иначе случайное нажатие закрывало приложение и рамка оставалась на лаунчере.

## Журнал состояния

Раз в минуту рамка дописывает строку в `PhotoFrame/Logs/frame.log` — он лежит в общей памяти
и читается по USB без adb:

```
2026-08-15 19:26:58  day   38/279  managed 9.6MB  native 38.7MB  free 542MB   cpu 11.9s  nightframes 0  clip -
```

Что показывают поля: `native` — где живут пиксели кадров, и именно там видно рост; `free`
и метка LOW — голодало ли всё устройство; `cpu` — крутилось ли что-то вхолостую;
`nightframes` — сколько кадров часов отрисовано; `slide` и `clip` — на чём рамка стоит.
Строку пишет фоновый таймер, поэтому если записи идут, а экран замер, встал именно UI-поток.

Файл переоткладывается на `frame.log.1` при 400 КБ, всё старше недели удаляется при запуске.

Просроченная проверка источников выполняется не сразу при пробуждении, а через минуту, отдавая
первые кадры показу. Набор кадров перечитывается не в потоке отрисовки, а порядок показа
переписывается, только когда он и правда изменился. Начало и конец проверки попадают в журнал.

## Настройка

1. Google Photos → альбом → **Поделиться** → **Создать ссылку** → скопировать.
2. Скопировать `secrets.props.template` в `secrets.props` и вписать ссылку:

   ```xml
   <GooglePhotosShareUrl>https://photos.app.goo.gl/...</GooglePhotosShareUrl>
   ```

`secrets.props` в `.gitignore`. Ссылка держится вне репозитория не как пароль, а как
«пропуск»: любой, кто её знает, видит альбом. Отозвать доступ можно в Google Photos.

`secrets.props` задаёт только **начальное** значение ссылки; дальше она меняется в настройках
без пересборки APK. Без заполненного `secrets.props` сборка проходит с предупреждением,
а рамка пишет на экране, что ссылка не задана.

## Тесты

```bash
dotnet test PhotoFrame/PhotoFrame.Core.Tests/PhotoFrame.Core.Tests.csproj
```

Покрыто то, что ломается молча:

- **Разбор страницы альбома** — извлечение ссылок, отсев аватаров на `/a/`, устранение дубля
  обложки, хосты `lh3`…`lh6` и пустой результат (он трактуется как ошибка, а не как «альбом пуст»).
- **Разбор ответов Immich** — адрес сервера, введённый без схемы или с лишним `/api`, порядок
  объектов альбома, `nextPage` строкой и `null`, пропуск удалённого на сервере и ответ, который
  вообще не является перечнем (страница входа обратного прокси).
- **Обход папок** — пропуск `cache`, `*thumbnail*`, `Trash` и скрытых каталогов, отсев
  неподдерживаемых расширений, стабильный алфавитный порядок.
- **Названия камер** — по парам Make/Model (`OLYMPUS CORPORATION` + `X-3,C-60Z`,
  `NIKON CORPORATION` + `NIKON D60`).
- **Ночной интервал** — переход через полночь.
- **Время клипа** — формат `m:ss`, расширение до `h:mm:ss` и отрицательная длительность,
  которую проигрыватель возвращает до подготовки файла.

## Ограничения

**Источник Google — ссылка на расшаренный альбом, а не Photos Library API.** Приложение
рассчитано на устройства, где официальный API недостижим: на рамке нет браузера (`ACTION_VIEW`
для `http` не разрешается ни во что, `CustomTabsService` отсутствует), нет Google Play Services,
device flow отвечает `Invalid device flow scope` на `photoslibrary`-scope, а токены живут 7 дней.
Ссылка на расшаренный альбом работает в таких условиях без авторизации.

Плата за это — разбор HTML страницы вместо документированного API. Ссылки на снимки ищутся
по шаблону `https://lh<N>.googleusercontent.com/pw/<токен>`; аватары авторов лежат на `/a/`
и под шаблон не попадают. Пустой результат трактуется как ошибка с внятным текстом на экране.
Часть кадров очень больших альбомов может подгружаться позже и в выборку не попасть.

**Число кадров.** Локальные папки не ограничены: файлы не копируются. Для общего альбома
предел настраивается (по умолчанию 2000, можно снять совсем), потому что каждый его кадр —
это HTTP-запрос и место на диске; при достижении предела об этом сообщается в статусе.

**32-битный ARM.** Пакеты `armeabi-v7a` существуют только для MonoVM. Для CoreCLR и NativeAOT
пакета `android-arm` нет, поэтому `UseMonoRuntime=false` и `PublishAot=true` ставить нельзя.
Следует оставаться на .NET 10 (LTS).

**TLS.** На API 27 нет Conscrypt ALPN, соединения идут по HTTP/1.1. На работу не влияет.
